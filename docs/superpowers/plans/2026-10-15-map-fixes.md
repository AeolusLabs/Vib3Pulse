# Map fixes: blank map, own avatar marker, friends strip + search

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** (1) The map never ends up silently blank on a weak or blocked connection. (2) The user's own marker is their avatar. (3) Friends sharing their location with me appear in a horizontal strip and in search, and tapping one flies the map to their avatar, wherever they are.

**Reported by:** the owner's business partner in Nigeria (grey map with only a purple dot) plus an owner request (Snapchat-style strip, see screenshots 2 and 3 of the 2026-10-15 message).

## Investigation findings (read-only, 2026-10-15)

1. **Blank map = no tile pictures arrived.** The grey is Leaflet's empty background. The map itself started (the purple dot is at the centre, the controls and the panel work). `client/src/pages/MapPage.tsx:37` loads tiles from `https://tile.openstreetmap.org/{z}/{x}/{y}.png` because no `VITE_MAP_TILES_URL` is set anywhere (`.env`, `.env.example`). That server works from here (200 in 0.22 s from the UK), so the fault is on the Nigerian side or in OSM's treatment of our traffic. Candidate causes, not yet distinguished:
   - OpenStreetMap's own tile servers are a free community service and their usage policy does not allow an app to depend on them in production; they can throttle or refuse. They also send no bytes-saving headers we can rely on.
   - Slow or filtered mobile network, data-saver mode or a content blocker on the partner's phone.
   - Both are invisible to us today because **the code has no tile error handling at all**: no `tileerror` listener, no fallback source, no message. A failed tile is just a grey square.
2. **Own marker is a plain dot, not an avatar.** `meIcon` (`MapPage.tsx:96`) is a fixed 16 px purple circle; the page never reads the user's own avatar. Friends do get the avatar pin (`friendIcon` uses `avatarPinSvg`, and `/api/map/nearby` already returns each friend's `avatar`), but only if the friend created an avatar; otherwise a photo or initial circle.
3. **Friends are limited to a 5 km box.** `/api/map/nearby` (`server/routes/map-routes.ts:122`) only returns friends inside the bounding box around the viewer (default radius 5 km). Search (`MapPage.tsx:283-290`) only looks at that same list, so a friend further away (another city or country, which is the normal case for a partner in Nigeria and friends in the UK) can never be found or jumped to. The search results also draw a photo or initial, not the avatar.
4. **There is no friends strip.** Nothing lists the friends who are sharing with me; the only entry point is a pin that happens to be on screen.

## Decisions for the owner

- **Tile provider (needed for Task 1b).** Options, honestly compared:
  - **A. A keyed tile provider (MapTiler, Stadia, Mapbox ...):** one env var, fast CDN, supports a dark style, no policy risk. Costs money at production volume and needs an account and key: check current pricing before choosing, I have not verified any.
  - **B. Our own cached tile proxy:** the server fetches tiles from a source, caches them and serves them from our domain with long cache headers. Cuts load on the source and speeds repeat views, but adds a server hop and still depends on the upstream source and its policy.
  - **C. Self-hosted vector tiles (Protomaps PMTiles file on Cloudflare R2 or similar) with MapLibre GL:** one static file, served from a CDN edge, much smaller downloads than picture tiles (the best fit for expensive mobile data) and works with caching. It is the largest change (swap Leaflet for MapLibre, restyle pins, about 0.8 MB of extra JS) and needs a build step for the map file.
  - **My recommendation:** do Task 1a now (resilience, no new provider), choose **A** as the quick durable fix once the partner's test (Task 0) shows OSM is the problem, and keep **C** as the proper long-term answer for African data costs.
- **Free tile research (2026-10-16): OpenFreeMap is the best free option, as Option D.** Free, commercial use allowed, no key, no request limit (public instance), OpenStreetMap data in vector form, styles Liberty, Bright and Positron, glyphs and sprites hosted by them, CORS open; the responses we fetched come through Cloudflare (cache HIT), so there is an edge cache. Caveats: it is run by one person on donations with no uptime guarantee, it needs MapLibre (vector, so it is the Option C client work without the hosting), and Nigerian latency is unmeasured. Attribution required: "OpenFreeMap (c) OpenMapTiles Data from OpenStreetMap". The current default (tile.openstreetmap.org) is against OpenStreetMap's own policy for a production app, and the other known free tiers are non-commercial only (MapTiler free, Stadia free) or tiny (Geoapify free 3,000 credits a day with a "follow" link). Recommended path: MapLibre + OpenFreeMap as primary, health detection + a second source as fallback, our own PMTiles later if OpenFreeMap proves unreliable.
- **Own marker style:** the same round pin badge as friends with a "You" ring, and the dot only as a fallback for people with no avatar and no photo.

## Global Constraints

- Privacy rules from the Map feature stay as they are: sharing off by default, only mutual follows see live position, positions rounded to about 100 m, rows older than 30 min treated as gone, blocking enforced, "selected friends" audience respected. The new friends endpoint must apply exactly the same filters as `/api/map/nearby` (it only drops the distance limit); no history, no exact coordinates, nothing for non-friends.
- Do not put anyone's age, email or date of birth in a payload.
- `npm run test:rooms`, `test:avatar`, `test:social -- --only=6` stay green; `npx tsc --noEmit` stays at the 10-error baseline; `npm run build` passes before any push. Match surrounding code style; theme tokens; 44 px targets; no horizontal scroll at 320-768 px.
- Schema changes: none expected. If one appears it is applied to the database in the same task.

## Review Focus

- A friend who is sharing but far away (outside 5 km, even in another country) must be findable and reachable by the strip and search.
- Friends not sharing with me (ghost, selected-audience without me, blocked either way, stale > 30 min, not mutual) must never appear in the strip, search or the new endpoint.
- Map tiles failing for any reason (offline, 403, 429, slow) must leave the person with a clear message, a retry, and the strip and lists still working.
- Own marker when the user has no avatar and no photo, and when location permission is denied (no marker at all, no crash).
- The strip with 0, 1 and 50+ friends; very long names; right-to-left names.
